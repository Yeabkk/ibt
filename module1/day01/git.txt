git log --author="name"             # Filter by author

git diff                            # Changes in working directory
git diff --staged                   # Changes in staging area
git diff <branch1> <branch2>        # Differences between branches
git diff <commit1> <commit2>        # Differences between commits
git diff <file>                     # Changes to specific file


git stash                           # Save current changes
git stash list                      # List all stashes
git stash pop                       # Apply most recent stash
git stash apply stash@{0}           # Apply specific stash
git stash drop stash@{0}            # Delete a stash
git stash clear                     # Delete all stashes

git reset <file>                    # Unstage a file
git reset HEAD~1                    # Undo last commit (keep changes)
git reset --soft HEAD~1             # Undo commit, keep changes staged
git reset --hard HEAD~1             # Undo commit, discard changes
git reset --hard <commit>           # Reset to specific commit

-Reset Types:

    --soft: Keeps changes staged
    --mixed (default): Keeps changes unstaged
    --hard: Discards all changes


git revert <commit> //creat new commit that undo a previus commit

Creates named references to specific commits (usually for releases).

git push origin v1.0.0

			Authentication Methods


There are two primary ways to authenticate with GitHub:
Method 1: SSH (Recommended)

SSH uses public-key cryptography for secure authentication.
Step 1: Generate SSH Key

# Generate a new SSH key
ssh-keygen -t ed25519 -C "your-email@example.com"

What this does:

    -t ed25519: Uses the modern Ed25519 algorithm (more secure)
    -C: Adds a comment (usually your email)


$ ssh-keygen -t ed25519 -C "john.doe@example.com"

Generating public/private ed25519 key pair.
Enter file in which to save the key (/Users/username/.ssh/id_ed25519): [Press Enter]
Enter passphrase (empty for no passphrase): [Type a secure passphrase or press Enter]
Enter same passphrase again: [Retype passphrase]

Your identification has been saved in /Users/username/.ssh/id_ed25519.
Your public key has been saved in /Users/username/.ssh/id_ed25519.pub.


Step 2: Add SSH Key to SSH Agent

# Start SSH agent
eval $(ssh-agent -s)

# Add your SSH key
ssh-add ~/.ssh/id_ed25519

$ eval "$(ssh-agent -s)"
Agent pid 12345

$ ssh-add ~/.ssh/id_ed25519
Identity added: /Users/username/.ssh/id_ed25519 (john.doe@example.com)

Step 3: Copy Public Key to Clipboard


cat ~/.ssh/id_ed25519.pub | clip

Step 4: Add SSH Key to GitHub

    Go to GitHub → Click your profile icon (top right) → Settings
    Click SSH and GPG keys (left sidebar)
    Click New SSH key button
    In the "Title" field, enter a descriptive name (e.g., "MacBook Pro")
    In the "Key" field, paste your public key (Ctrl+V or Cmd+V)
    Click Add SSH key

Step 5: Test SSH Connection

ssh -T git@github.com

execpted out put 

Hi username! You've successfully authenticated, but GitHub does not provide shell access.



Method 2: HTTPS with Personal Access Token (PAT)

HTTPS is easier for beginners but requires a Personal Access Token for authentication.
Step 1: Create a Personal Access Token on GitHub

    Go to GitHub → Click your profile icon → Settings
    Click Developer settings (bottom of left sidebar)
    Click Personal access tokens → Tokens (classic)
    Click Generate new token → Generate new token (classic)

Step 2: Configure Token Settings

Token name: "My Git Token" or descriptive name
Expiration: Select 30, 60, 90 days, 1 year, or No expiration
Select scopes (permissions):
  ☑ repo (Full control of private repositories)
  ☑ workflow (Update GitHub Action workflows)
  ☑ admin:public_key (Manage public keys)


example 
Token name: MacBook Git Access
Expiration: 90 days
Scopes: repo, workflow


    Click Generate token
    Copy the token immediately (you won't see it again!)

Step 3: Store Token Securely

Option A: Use Git Credential Manager (Recommended)

# On macOS:
brew install git-credential-manager

# On Windows (comes with Git for Windows):
# Already installed

# Configure Git to use credential manager
git config --global credential.helper manager-core

Option B: Store in Local Config

# Create a file to store credentials (not recommended for production)
nano ~/.git-credentials

# Add this line:
https://username:YOUR_TOKEN@github.com

# Set proper permissions
chmod 600 ~/.git-credentials

# Configure Git to use this file
git config --global credential.helper store

Step 4: Test HTTPS Connection

git clone https://github.com/YOUR_USERNAME/test-repo.git
# When prompted, use your username and the PAT as password

Part 3: Common Connection Issues & Solutions
Issue 1: SSH Key Permission Denied

Error:
Permission denied (publickey).
fatal: Could not read from remote repository.
solution:
# Check if SSH key exists
ls -la ~/.ssh/

# If not, generate a new one
ssh-keygen -t ed25519 -C "your-email@example.com"

# Verify SSH key is added to agent
ssh-add ~/.ssh/id_ed25519

# Test connection
ssh -T git@github.com


Issue 2: Repository Not Found

Error:

fatal: repository 'https://github.com/username/repo.git' not found

soln:

# Verify remote URL is correct
git remote -v

# Update if wrong
git remote set-url origin https://github.com/CORRECT_USERNAME/repo.git

# Test with SSH instead
git remote set-url origin git@github.com:username/repo.git


Issue 3: Token Expired (HTTPS)

Error:

fatal: Authentication failed for 'https://github.com/...'

soln:

# Generate a new Personal Access Token on GitHub
# Then clear stored credentials

# On macOS/Linux:
git credential-manager uncache https://github.com

# On Windows:
git credential-manager remove

# Next push will prompt for new credentials
git push origin main

Issue 4: Wrong User Configured

Error: Commits show wrong author

Solution:

# Check current configuration
git config --global user.name
git config --global user.email

# Update if needed
git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"

# Or configure for specific repository
cd /path/to/repo
git config user.name "Your Name"
git config user.email "your-email@example.com"

Part 5: Best Practices for GitHub Connection
Practice	Description
Use SSH	More secure than HTTPS, no need to enter credentials repeatedly
Protect Keys	Never share private SSH keys; use strong passphrases
Rotate Tokens	Refresh PATs regularly; set expiration dates
Use Credential Manager	Don't store passwords in plain text
Verify Host Key	First SSH connection will ask to verify fingerprint—check it matches GitHub's
Configure User Info	Always set proper name/email for commits
Multiple Machines	Generate unique SSH keys for each computer
Keep Keys Safe	Back up SSH keys securely; don't commit .ssh folder
